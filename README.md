# Codex usage

在 Mac 上查看本机 Codex 日志里的 Token 用量和额度快照。Python 后端只在本机监听，读取现存日志、生成 SQLite 索引，浏览器展示图表。不调用模型 API，不上传日志。统计不等同于整个账户的官方用量。

## 新 Mac 安装与启动

目前是源码项目，不是独立安装包。首次在另一台 Mac 上安装尚未实测；以下步骤说明当前代码的实际依赖。需要能访问自己的 Codex 日志，并安装 Codex 桌面应用及其 Data 插件。插件的获取和可用性取决于 Codex 环境，仓库本身不包含该构建工具。

1. 克隆仓库并进入目录：

   ```sh
   git clone https://github.com/par73e/Codex-usage-4-Mac.git
   cd Codex-usage-4-Mac
   ```

2. 检查 Python 3.9+、npm，以及 Codex 自带的 Node 和 Data 插件构建器。系统 npm 用于安装依赖，启动时使用下方固定位置的 Codex Node；安装 Node/npm 的方式由使用者自行选择。插件可能有不同版本，只要包含该构建脚本即可。

   ```sh
   python3 --version
   npm --version
   "$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node" --version
   ls "$HOME"/.codex/plugins/cache/openai-curated-remote/data-analytics/*/scripts/data-app.mjs
   ```

   若后两项找不到，先在 Codex 中安装或启用相应组件；不能仅靠 `npm install` 替代插件构建器。不同 Codex 版本的路径或构建工具兼容性未验证。

3. 安装前端依赖。此步骤需要网络：

   ```sh
   cd web
   npm ci
   cd ..
   ```

4. 如需读取 `.jsonl.zst` 压缩存档，还需安装 `zstd`，例如已安装 Homebrew 时运行 `brew install zstd`。普通 `.jsonl` 不需要它。

5. 启动并保持终端窗口打开：

   ```sh
   python3 -m backend.app --port 8765
   ```

   浏览器访问 http://127.0.0.1:8765。也可双击 `start.command`。停止服务时在启动它的终端按 Ctrl+C。程序不自动开机启动。

首次启动会扫描日志、创建 `var/usage.sqlite` 并构建 `web/dist`，耗时取决于日志量。启动会将本机统计快照写入被 Git 忽略的 `web/src/data.json`。不要上传该文件、`var/` 或 `web/dist/`：它们可能包含个人用量和会话信息。

### 配置与排错

- 默认日志根目录为当前用户的 `~/.codex`，用户名不同无需改代码。自定义根目录可用 `python3 -m backend.app --log-root /path/to/codex-root`；该目录下应有 `sessions/`、`archived_sessions/` 等。索引仍位于本项目 `var/usage.sqlite`。切换日志根目录前请备份或移走现有索引，避免混用；不要修改原始日志。
- 端口冲突时使用 `python3 -m backend.app --port 8766` 并访问相应地址。服务只监听 `127.0.0.1`。
- 如果提示找不到 Data 构建工具，请检查上面的插件路径；若有已构建且可信的 `web/dist`，可用 `--skip-build` 启动，但全新克隆不包含构建结果。
- 页面没有数据时，检查 `~/.codex/sessions` 是否存在日志，以及终端报错；没有本机历史或日志缺失不代表账户用量为零。
- 运行期间不自动扫描日志；点击顶部刷新按钮或“立即同步”才读取新日志。关闭浏览器不会停止后端。

### 数据流与文件索引

`~/.codex/sessions/` 与 `~/.codex/archived_sessions/` → `backend/logfiles.py` 发现并只读流式解析普通及压缩日志 → `backend/engine.py` 增量索引、按 `response_id` 去重并关联配置 → `var/usage.sqlite` 保存派生数据 → `backend/app.py` 提供本机 HTTP 接口 → `web/src/content/dashboard/` 展示图表。

程序也只读 `~/.codex/state_5.sqlite` 和 `session_index.jsonl` 补充会话名称；额度快照从日志中提取。旧格式的累计读数由 `backend/legacy_intervals.py` 差分为估算区间。模型和推理强度来自日志配置关联，并非服务端最终路由的独立证明。

给维护者和 agent：先读本文件和 `DESIGN.md`；修改前端前先读 `web/AGENTS.md`。`backend/quota.py` 处理额度，`tests/` 包含后端和前端测试，`web/package-lock.json` 固定前端依赖。下方保留完整功能和统计口径说明。


本机运行的 Token 用量浏览器工具。读取现存 Codex 响应日志，不调用模型 API、不上传日志、不修改源日志。

## 启动

在项目根目录运行：

```sh
python3 -m backend.app --port 8765
```

然后打开 <http://127.0.0.1:8765>。也可以双击 `start.command`（终端窗口需保持运行）。

后端使用 Python 3.9+ 标准库；读取 `.jsonl.zst` 存档还需要本机 `zstd` 工具（当前机器已安装）。压缩内容以流式只读方式解码，不会解压到源目录。前端已切换源码构建，依赖固定在 `web/package-lock.json`，本机已安装到 `web/node_modules`；启动时使用 Codex 附带的 Node，并自动查找已安装的 Data 构建入口构建一次页面，不再固定插件版本目录。后续日志同步不需要构建、不调用模型，也不需要打开 ChatGPT。尚未做成脱离本机开发环境的独立安装包。

启动时扫描一次日志并构建页面。运行期间不会自动扫描；点击顶部刷新按钮或“立即同步”才读取新增日志、更新索引和图表。网页首次打开会读取已有快照，不触发日志扫描。关闭网页不会停止后端；按 Ctrl+C 停止服务。当前不包含开机自启或系统后台守护。

## 使用

- 时间范围使用 Ant Design 的统一日期时间选择器，可点选日历、小时和分钟，也可直接输入或粘贴 `2026-10-23 01:37`。点击日历中的首尾端点或顶部“开始 / 结束”可随时切换编辑；长按端点约 0.1 秒后拖动日期，保留原时分，在日历左右边缘停留可跨月。首尾不能互相越过，同一天也可分别操作“起 / 止”标记。调整先保存在草稿中，统一点“应用时间范围”更新统计；按 Esc 或点击弹窗外取消。分钟步长为 1，不显示秒。起点包含、终点不包含。
- 面板提供最近 1/6/12/24 小时、今天、昨天、最近 7/30 天，以及最近 5 次使用记录。历史记录保留分钟、时区和是否跟随现在；重新选择相对范围时按当前时间重新计算。
- 默认北京时间，可选其他时区；夏令时存在歧义的输入会要求改用 UTC。
- 粒度支持 1 小时、6 小时、12 小时和天，首尾分组按查询区间裁剪。
- 时间跨度很大时，每模型最多绘制 120 个概览柱，合并相邻时段并显示提示；悬浮可查看该柱的完整起止时间。拖动显示范围缩小到 120 个原始时间桶以内，会自动恢复所选粒度。完整源记录、区间总量和额度快照均保留，Token 与额度图继续共用缩放范围。
- 会话只列出该时间内有正数用量的候选，支持搜索、全选、清空、多选。
- 页面顺序为所有模型合计用量、账户剩余额度、各模型用量。合计图与分模型图共用“推理强度／用量构成”切换和颜色；推理强度显示整个所选区间的 Token 占比，旧日志区间估算单独着色；可展开合计用量表和原始旧日志观测区间表，表格支持分页。日期、时区、会话筛选和缩放联动。
- 每模型一张图。推理强度模式显示全区间 Token 占比，用量构成模式显示缓存输入、非缓存输入和输出。
- 默认统一纵轴；用量较小的模型可切换独立纵轴查看。
- 右上角直接选择 **浅色 / 深色 / 跟随系统**，不再显示 ChatGPT、发布或编辑入口。外观偏好随页面重载保留。
- 手动同步：顶部 Updated 旁和正文的“立即同步”都会调用本机后端扫描日志，页尾显示最近检查时间。
- “结束时间跟随现在”开启时，结束分钟自动前进；提交自定义日期时间会关闭它，固定历史范围不会被自动扩大。“最近 N 小时/天”的起止两端一起滚动，“今天”从当日零点开始，“昨天”为固定完整一天。
- 数据更新保留时间、粒度、颜色、会话选择和图表缩放；筛选和主题也会在浏览器中记住。断线时保留最后一次数据并显示提示；恢复服务后点击刷新重试。
- 图表右上角原生菜单可检查本图的已筛选源记录。页面底部可展开数据范围说明。
- Token 图下方显示账户剩余额度，按日志中的额度桶和窗口长度分别绘制 0～100% 快照点图（点之间不连线）。额度图共用时间范围、时区和缩放，保留原始快照时间；会话和压缩筛选不改变账户额度。
- “额度周期”来自日志，和图表展示范围是两个概念。顶部可以选择任意起止分钟；额度图旁的“当前展示”显示实际筛选／缩放区间。恢复点仅比普通点大 1px，无额外外圈；恢复区间使用淡底色。
- 30 天周期的历史额度图已移除；原始快照仍保留在日志和来源数据中，其他额度周期继续显示。
- 鼠标停留在额度点或恢复区间时，更新快照不会重置同一条记录的悬浮框；移开鼠标或按 Esc 关闭。后台更新保留当前可交互图表，用户主动改变筛选时才暂时禁用旧结果。
- 悬浮额度点查看观测时间、已用／剩余百分比、窗口长度和当时预计重置时间。“显示缺失记录背景”控制超过 15 分钟没有快照的灰色背景，默认关闭，所有额度图共用并记住选择；关闭后保留统一底色和淡紫色恢复标记。最后一条记录之后不推算额度。
- 额度大幅回升会显示观测区间和恢复记录表，恢复记录默认折叠，点击展开。短区间另以最小 8px 浅紫标记提示，悬浮显示真实起止时间，标记宽度不代表持续时间。当前规则为相邻观测已用比例下降至少 10 个百分点，或下降至少 5 个百分点并报告已用 0%；仅后者的 0% 观测标为“恢复满额”。这不是服务端重置事件，也不证明原因。小幅回跳不标记。

## 数据范围

主来源是 `~/.codex/sessions`、`~/.codex/archived_sessions`，同时读取 `.jsonl` 和 `.jsonl.zst`。压缩文件按文件身份、大小和修改时间缓存；未变化时不重复解码，损坏的压缩帧会回滚本文件的本轮索引，保留上次成功结果。只读 `state_5.sqlite` 和 `session_index.jsonl` 补充会话名称等信息。

本地派生数据保存在 `var/usage.sqlite`，不写回源目录。旧格式累计 `token_count` 取相邻有效累计读数之差，保留为独立的观测区间。重复快照去重，只补入本会话逐响应明细出现之前的历史；首条以创建时间为下界。可确认的子会话继承计数仅作基线，新子会话的实际首笔用量保留。同时间多读数取最大观测累计值并标为粗时间记录，不重复相加。累计回退另起估算区间；缺失起点标为未知并按观测时段归入，不声称精确时间。跨桶或部分筛选使用整数累计比例分配，保证区间拆分加总守恒；区间内不表示实际均匀消耗。模型、强度、压缩类型、响应次数不作推断。响应明细和额度快照各自展示最早可读日期。聊天索引的 `.jsonl` 路径若存在对应 `.jsonl.zst`，视为压缩存档可用，不计为历史缺失。响应级用量按 `response_id` 去重；缓存输入已经包含在输入中，推理输出已经包含在输出中。已确认的上下文压缩调用默认计入，可以排除；旧累计无法识别压缩类型，仍作为单列估算保留。模型、推理强度按当时的日志配置关联；缺失关联进入“未知”，不猜测。记录缺失不代表账户零用量，也不能重建已缺失的历史。

额度来自 `event_msg/token_count.rate_limits`，仅保存时间、额度桶、窗口、百分比和预计重置时间。多个文件中的相同快照合并，同一窗口同一时刻百分比冲突的记录排除。旧索引首次升级会自动重新读取源日志以回填额度。额度是账户范围；本地日志不含可靠账户身份，不能区分切换账户，也不能保证覆盖其他设备。程序不会主动调用账户额度接口，不记录 credits 余额或认证信息。

后端 `/api/v1/snapshot` 提供完整索引的一致快照；轻量 `/api/v1/status` 用于检测更新。只有版本改变才重新下载源记录。查询接口校验快照版本，版本竞争时网页自动协调重试，避免会话候选、图表和源检查混用版本。浏览器不会自行读取任意本地文件。

## 项目结构

- `backend/engine.py`：增量索引、去重、配置关联、时间分桶、会话与模型聚合。
- `backend/app.py`：仅回环地址 HTTP 服务、后台自动扫描、同版本快照和查询接口。前端构建只在启动时执行。
- `backend/logfiles.py`：发现普通／压缩日志，调用本机 zstd 流式读取并校验解码完成。
- `backend/legacy_intervals.py`：旧累计快照校验、去重、粗时间／继承基线识别、观测区间与整数时长分配。
- `web/src/content/dashboard/TotalUsageChart.jsx`：所有模型合计图、合计用量表及原始旧区间表。
- `backend/quota.py`：额度快照的字段白名单、校验、去重和恢复观测区间。
- `web/src/content/dashboard/QuotaCharts.jsx`：共用时间轴的额度快照点图、观测提示和恢复记录表；`quota-view.js` 处理缩放与时间位置。
- `web/src/content/dashboard/use-live-usage.js`：手动同步与快照更新。
- `web/src/content/dashboard/TimeRangePicker.jsx`：带时分、快捷范围和最近使用的选择器；`date-range.js` 处理时区、相对范围及记录验证。
- `backend/legacy_reader.py`：已有命令行解析器中的字段、时间和用量验证基础。
- `web/src/content/dashboard/`：页面和图表；保留共享运行时的来源检查、主题和现有图表编辑入口。
- `web/src/theme.css`：自适应深浅主题色。
- `tests/test_engine.py`：合成日志测试，不使用私人日志正文。
- `tests/test_live_sync.py`：后台追加、半行、失败恢复、并发去重、清空、HTTP 同步与来源限制。
- `docs/design.md`：原设计稿，作为历史设计依据；当前实现状态见本文。
